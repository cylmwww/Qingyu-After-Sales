# 测试策略与覆盖范围

功能测试优先通过 `create_app → lifespan → build_container → HTTP → LangGraph → 工具/检索 → SQLite` 执行。数据库使用临时 SQLite，知识来自仓库 `knowledge/`，订单由生产种子函数生成。模型协议场景通过配置的 base URL 连接本机 HTTP 替身，内部图、检索、工具与数据库保持真实。

## 失败模式

| 范围 | 需要防住的失败 |
|---|---|
| 应用启动与 API | 显式配置未进入生命周期，管理令牌绕过，错误缺少追踪信息 |
| 知识问答 | 知识没有入库，引用不存在，回答与证据不一致 |
| 订单与确认 | 提案提前写库，确认目标可篡改，跨用户/会话执行，重放重复写入 |
| 路由与护栏 | 问候前缀掩盖业务意图，政策咨询产生写提案，注入请求未拒绝 |
| 多跳检索 | 证据充分仍继续，无限循环，评分服务异常丢弃已有证据 |
| 查询改写 | 空列表、缺字段、坏 JSON、HTTP 拒绝阻断原问题检索；空白未清理或扩展数量失控 |
| 忠实度 | 不支持的候选提前发布或持久化，纠正后的回答未成为唯一最终回答 |
| 工具适配 | 订单读取失败未回退知识，本地 MCP 未由生产注册表装配，结果未进入生成请求 |
| SSE | token 与最终回答不一致，缺少结束事件，最终结果未保存；UTF-8/CRLF/EOF 切块损坏 |
| JSON 与排序 | 非对象根被接受，畸形输入未拒绝，RRF 受原始分数影响或修改输入 |
| 缓存与重试 | 查询或 top_k 混淆、订单数据被缓存、TTL 无效、Redis 故障传播、鉴权错误被重试 |
| 压缩与文档 | 最近对话丢失或乱序、压缩修改输入、表格拆散、敏感信息泄漏、相似政策误删 |
| 数据库 | 补种覆盖已有业务数据、退款与幂等记录提交后丢失、跨用户订单可读 |

独立测试用于有输入空间价值的解析、算法和外部适配边界，不能替代完整功能覆盖。不测试私有成员、源码结构、固定日志/提示词文案、DTO 默认值或固定资产数量。

## 本轮补充核对

首次整理时，独立工作树只有两个前端测试文件，后端 `tests/` 被忽略而未进入工作树。首批提交建立了 46 个后端用例。合并原项目后发现另一批未跟踪的旧测试，本轮对其单独运行：163 例通过，再与首批基线按逐测试 context 比较分支，而非凭总覆盖率删除。

首次比较的 132 个应用覆盖 context 中，45 个用例执行的分支均已被首批基线覆盖；其余逐项核对并补入口场景。有 31 个旧评估用例依赖未纳入仓库的 `eval/`，不属于可独立复现的仓库套件，未将其恢复纳入版本管理。

原批次的 163 个测试函数保留整理为 55 个，移除 108 个旧函数，另补 18 个参数展开后的 HTTP 场景。与首批 46 例合计为 119 例：29 个 HTTP 场景、5 个集成用例和 85 个独立边界用例。前端仍为 10 例，本轮没有修改前端。

整理内容：

- 删除重复 BM25/RRF/解析、固定工具数量、私有确认状态、固定文案与日志、模拟检索循环等旧测试；保留已有 JSON/RRF 和完整 HTTP 基线。
- 多跳检索、改写失败、忠实度纠错、执行降级和本地 MCP 改由真实 HTTP/生产装配承接。
- 保留查询列表清理、缓存 TTL/Redis 异常、压缩、模型适配、文档解析、分词与数据库集成测试；不把这些宣称为端到端覆盖。
- 压缩断言补上最近消息顺序与输入不变；退款测试按实际证明的“提交后持久化”命名，不再声称已证明事务回滚或完整幂等执行。
- 意图分类输入移到 `tests/fixtures/intent_queries.jsonl`，删除固定条数和历史编号断言；删除无人使用的 HTML 夹具。

旧文件原本未跟踪，因此本次 Git 中保留项显示为新增文件，删除项不会显示为 `D`。这不表示又新增了一整套未经核对的旧测试。

剩余未承接的旧覆盖主要为日志、CLI 元信息展示、空实现、手拼组件产生的权限/循环路径，以及不同应用工厂分支。删除有害断言不以保留这些覆盖弧为目标；不修改生产代码以追求覆盖百分比。

## 覆盖矩阵

| 测试 | 覆盖范围 |
|---|---|
| `e2e/test_runtime.py` | 配置贯穿生命周期、临时数据库、管理令牌、就绪与能力、错误与追踪 |
| `e2e/test_customer_flows.py` | 知识引用、订单物流、取消确认与重放、用户/会话范围、路由与咨询、注入拒绝、SSE 持久化 |
| `e2e/test_model_transport.py` | 真实模型客户端 HTTP 协议、结构化解析、数组回答降级 |
| `e2e/test_model_paths.py` | 多跳充分/不足/评分异常、改写失败、工具降级、本地 MCP、纠错最终结果发布与持久化 |
| `integration/` | 混合检索装配、真实数据库/仓库/退款工具/种子补齐；不宣称完整 HTTP 退款或事务回滚 |
| `unit/` | JSON/RRF、查询清理、缓存、压缩、外部模型适配、非 Markdown 解析、脱敏、分词、重试等独立边界 |
| 前端 Vitest | SSE 解码边界、回答正文与引用展示、来源去重 |

仍未验证真实 DeepSeek、BGE/CrossEncoder、Unstructured、PostgreSQL、Redis、Qdrant 或远程 MCP。完整退款/退货/商品 HTTP 流程、并发确认、确认过期、原始 provider 流协议仍有缺口。前端 Node/SSR 测试不覆盖浏览器停止生成、切换会话、确认卡片交互或持久化恢复。首轮的浏览器验证是一次运行证据，不计为自动浏览器回归。

## 运行与产物

后端：

```bash
python -m pytest -q
```

前端：

```bash
npm --prefix frontend test
```

逐测试分支覆盖：

```bash
python -m pytest --cov=app --cov-branch --cov-context=test --cov-report=json:output/coverage.json --basetemp=output-test-run
```

`--basetemp` 必须是专用输出目录，pytest 会在运行前清理。每个 HTTP 场景在临时目录保存稳定语义 JSON manifest，移除耗时、时间戳、随机 ID 与提示词全文。模型响应和意图输入夹具位于 `tests/fixtures/`。测试不依赖本地 `eval/`。

覆盖报告用于定位缺口，不设置总百分比目标，不凭汇总百分比删除测试。第一轮修复的应用配置归属与 JSON 根类型问题已有入口场景和解析回归；本轮只整理测试与说明，不修改生产行为。
