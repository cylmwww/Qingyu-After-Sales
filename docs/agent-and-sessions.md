# 业务工具、多轮对话与任务恢复

只读业务模式将知识检索、模拟业务查询与任务状态放进同一个会话。用户可以询问政策、订单、退款解释与进度，并在缺少条件时继续补充。基础环境见[运行说明](setup.md)，页面入口见[工作台](workbench.md)。

## 业务能力与身份

| 工具 | 用途 |
| --- | --- |
| `search_knowledge` | 检索政策与 FAQ。 |
| `read_policy_context` | 读取精确版本的父片段或关联条款。 |
| `get_order` | 查询订单及支付、商品单元等记录。 |
| `get_after_sales` | 查询售后与退款记录。 |
| `get_logistics` | 查询原订单出库物流。 |
| `calculate_refund` | 基于确认范围和冻结支付份额进行整数退款预估。 |

所有业务记录为虚构静态种子，身份由服务端 `AGENT_CUSTOMER_ID` 绑定，业务快照由 `BUSINESS_SNAPSHOT_ID` 指定。提供订单号不构成授权；服务端核对订单归属，客户端不能自选可信客户身份。

退款预估、审批与实际到账是不同结果。工具不执行退款、取消订单、改价或创建人工工单；质量自述不等于已核实质量问题。

## 开始一次对话

在客服页填写访问令牌，保持“只读业务模式”开启，输入例如：

- “ORD-006 退款金额为什么不是 199 元？”
- “ORD-010 退款到了吗？”
- “ORD-006 物流在哪里？”

缺少订单、退货原因、申请时间或商品范围时，页面提示补充。仅填写已确认条件，时间使用带时区的完整值；商品单元从 1 开始编号。

“确认或修正业务条件”支持 JSON，例如下列字段形状。订单行和赠品必须来自当前订单，不能直接套用到其他订单：

```json
{
  "return_reason": "no_reason",
  "after_sales_applied_at": "2026-10-07T10:00:00+08:00",
  "selections": [{"line_id": "LINE-006-01", "unit_indices": [1]}],
  "gift_returned_line_ids": ["LINE-006-03"]
}
```

明确 `null` 表示撤回旧事实，未提供字段保留原值。切换订单会清除旧订单范围与条件。修正可能使旧结果失效；既有任务预算不因此重置。

## 选择执行策略

默认 `auto` 根据业务意图选择快速知识问答或动态步骤，快速路径在证据不足时可升级。业务意图包括政策、订单、退款金额、退款进度和物流；它不是自动判定 FAQ、单跳与多跳难度的分类器。

| `configs/agents/` 预设 | 行为 |
| --- | --- |
| `auto.v1.1.0.json` | 正常自动路由。 |
| `fast.v1.1.0.json` | 锁定快速路径。 |
| `fixed.v1.1.0.json` | 锁定固定多步策略。 |
| `dynamic.v1.1.0.json` | 锁定 Planner–Executor 动态策略。 |

可在“知识与配置”页选择 Agent 预设，或设置服务默认环境变量后重新创建后端：

```dotenv
AGENT_CONFIG_PATH=configs/agents/auto.v1.1.0.json
AGENT_CUSTOMER_ID=CUST-001
BUSINESS_SNAPSHOT_ID=SNAP-DEMO-20261009
```

固定策略预设用于明确控制路径，不代表效果优于自动路由。规划、结构化执行与生成复用配置的模型服务；响应协议需匹配供应商，见[模型配置](setup.md)。

关闭“只读业务模式”后使用 `POST /api/chat` 单轮知识问答，不进行业务任务编排或独立审核。证据审核见[检查与纠错](evidence-review.md)，可选观察驱动循环见[复杂任务循环](workbench.md#复杂任务循环)。

## 取消、重试与恢复

同一会话只运行一个任务。等待任务应补充条件或取消；失败、失联任务需要显式恢复，或先取消再开始新任务。

页面关闭或断网不会自动取消后台任务。刷新后重新填写访问令牌，使用“重新连接”读取持久事件与任务结果；不确定提交是否到达时使用“重试原提交”，保留相同请求 ID，避免创建重复任务。

“取消任务”使旧执行失效，迟到结果不能覆盖新任务。浏览器会话存储保存会话、任务 ID 与待提交输入；访问令牌只保存在内存。任务状态在数据库中持久化，浏览器状态不是跨会话长期记忆。

## HTTP 接口

受保护接口使用 `Authorization: Bearer <API_ACCESS_TOKEN>`。完整字段见后端 `/docs`。

| 接口 | 作用 |
| --- | --- |
| `POST /api/agent/sessions` | 创建会话。 |
| `GET /api/agent/sessions` | 列出当前服务身份可访问的会话。 |
| `GET /api/agent/sessions/{session_id}` | 读取会话与近期任务。 |
| `POST /api/agent/chat` | 新任务、澄清、修正或恢复，通过 SSE 返回。 |
| `GET /api/agent/tasks/{task_id}` | 读取任务状态、预算和冻结配置。 |
| `POST /api/agent/tasks/{task_id}/cancel` | 取消任务。 |
| `GET /api/traces/{trace_id}` | 读取执行追踪。 |
| `GET /api/traces/{trace_id}/events` | 重放事件，支持 `after` 或 `Last-Event-ID`。 |

初次请求形状如下，两个 UUID 需替换为实际会话 ID 与新生成的请求 ID：

```json
{
  "session_id": "00000000-0000-0000-0000-000000000001",
  "request_id": "00000000-0000-0000-0000-000000000002",
  "action": "new",
  "question": "ORD-006退款金额为什么不是199元？",
  "facts": {"order_id": "ORD-006"}
}
```

`clarify`、`revise`、`resume` 必须带当前 `task_id`。相同会话与请求 ID 的相同载荷返回原任务，载荷不同返回 409；会话被占用返回 409，并发已满返回 429。无权访问的会话、任务和业务追踪按不可访问处理。

## 持久化与预算

任务使用 LangGraph 检查点和操作记录复用可靠结果。外部调用已开始但结果尚未可靠落盘时，崩溃恢复仍可能重执行；追踪会记录该窗口，不保证外部调用恰好一次。恢复时会核对代码、依赖、配置、知识及业务指纹，不兼容则拒绝。

默认请求限时 120 秒，任务主动执行限时 300 秒；请求模型/工具上限为 12/10，任务上限为 30/25，累计 token 预算为 60000。默认最多 6 步、2 次重规划，连续无进展会退出。检查、修复和补查共用预算，澄清等待不消费主动执行时间，恢复不抹去已消费额度。

任务结果、工具状态、调用次数与失败原因可在追踪页查看。接口完成只说明执行状态，不能当作退款完成或业务语义正确。Agent 检查点和操作记录目前不自动成组清理。
