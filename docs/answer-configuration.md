# 查询改写、上下文与生成配置

答案配置决定如何处理检索问题、补充政策上下文和约束生成。它复用已有知识索引，不需要因开启上下文补充而重新向量化。默认使用原问题、仅命中片段与基础生成提示词。

## 选择答案预设

文件位于 `configs/answers/`：

| 文件 | 查询改写 | 上下文 | 排列与生成 |
| --- | --- | --- | --- |
| `q0-baseline.v1.0.0.json` | 关闭 | 仅命中 | 按排名，基础提示词 |
| `q1-rewrite.v1.0.0.json` | 抽取式改写 | 仅命中 | 按排名，基础提示词 |
| `q2-parent-related.v1.0.0.json` | 关闭 | 父片段与关联条款 | 按排名，基础提示词 |
| `q3-grouped.v1.0.0.json` | 关闭 | 父片段与关联条款 | 按种子与关联分组，基础提示词 |
| `q4-prompt.v1.0.0.json` | 关闭 | 仅命中 | 按排名，加强生成约束 |

选择父片段补充适用于命中片段缺少条件或例外的情况；改写适用于希望将长问题中的原文短语作为额外检索线索的情况。两者都会改变输入或调用量，不保证每个问题都受益。

## 应用配置

在“知识与配置”页选择答案预设并应用，检查有效配置；正在运行及恢复的任务沿用原快照。

也可在 `.env` 中设置服务默认值：

```dotenv
ANSWER_CONFIG_PATH=configs/answers/q2-parent-related.v1.0.0.json
```

```bash
docker compose up -d --force-recreate backend
```

单次查询可指定：

```bash
docker compose exec backend python -m backend.cli query --answer-config configs/answers/q2-parent-related.v1.0.0.json --question "活动商品退货时赠品和运费怎么处理？"
```

可与 `--config`、`--retrieval-config` 和 `--index-id` 组合。混合召回依赖对应索引的 BM25，见[召回配置](retrieval.md)。无密钥演示沿用其 Compose 项目名和 `--env-file`。

## 查询改写如何工作

开启后最多执行一次抽取式模型调用，默认最多 8 个短语、300 输出 tokens。每个短语必须逐字出现在原问题中，不能新增同义词、业务事实、已核实状态或过滤条件。

原问题始终参与检索。有效改写形成第二个查询，两路使用相同过滤与召回配置，再按片段 ID 跨查询 RRF 合并；如启用重排，合并后仅用原问题重排一次。生成回答也继续使用原问题。

无变化或内容校验不通过时，追踪明确记录原因并使用原查询；模型接口失败则记录技术失败，不伪造改写成功或切换供应商。

## 父片段与关联条款

`hits-only` 仅保留选中的命中；`parent-related` 尝试读取同索引、同文档版本的父片段，并跟随种子元数据中的 `related_refs`、`evidence_refs` 一跳补充精确版本条款。

补充仍需满足店铺、品类和已确认事件时间限制。未知时间不等于默认采用最新版本；关联版本缺失或被过滤时会记录原因，不拿其他版本顶替。默认最多补充 12 个片段，父片段默认有界，不代表载入整篇政策。

同一片段、相同原文范围或被父片段完整包含的正文会去重，并保留来源映射。不同版本、条件或未完全包含的范围不会随意拼成新条款。分组排列只改变呈现顺序，不改变证据选择优先级和权限。

## 输入与生成预算

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `generation.evidence_token_budget` | 6000 | 证据及其来源、条件、引用标识等的预算。 |
| `generation.input_token_budget` | 12000 | 系统提示、原问题、证据及消息封装的输入预算。 |
| `generation.max_output_tokens` | 1200 | 回答生成输出上限。 |

候选超限时按完整片段淘汰，避免只留下半条规则。父片段放不下时尝试原命中子片段；原问题与基础消息本身已超限时拒绝模型调用。预算计数是 tokenizer 估算，与供应商实际用量分开记录。

最终上下文重新生成引用映射，引用抽屉显示实际入模片段。加强生成提示词强调时间、版本、条件、例外与未知状态，但不增加独立审核调用。独立证据检查和修复见[审核说明](evidence-review.md)。

配置变更应新增 `id + version`。同版本内容冲突会被拒绝，历史请求继续保留原配置与上下文。

## 在追踪中检查

关注原问题与改写短语、校验或拒绝原因、各查询召回、跨查询融合、父与关联补充、去重、预算淘汰、最终顺序和引用映射。模型调用记录保留角色、提示词版本、耗时和供应商用量；未知用量与费用为 `null`。

上下文覆盖更完整不代表业务结论正确。政策适用与时间条件仍需要结合用户确认事实和业务证据判断。
