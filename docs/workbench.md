# 客服工作台与复杂任务循环

青屿售后将客服对话、请求追踪、知识与配置放在同一个工作台中。本页适合第一次打开项目的读者，介绍无密钥体验、页面操作和可选任务循环。真实模型与本机运行见[运行说明](setup.md)。

## 无密钥部署

需要已运行的 Docker Engine 与 Compose v2，并预留 5438、8008、5178 端口。在仓库根目录运行：

```bash
docker compose -p qingyu-demo --env-file .env.mock.example up -d --build
docker compose -p qingyu-demo --env-file .env.mock.example ps --all
docker compose -p qingyu-demo --env-file .env.mock.example logs init
```

该方式直接使用模拟配置，不需要创建或覆盖 `.env`。数据库就绪后，`init` 自动应用迁移、初始化检查点、校验业务种子，并复用兼容知识索引或首次入库；完成后才启动应用服务。

| 页面 | 演示地址 | 用途 |
| --- | --- | --- |
| 客服对话 | http://127.0.0.1:5178/ | 提问、确认条件、查看引用和任务进度。 |
| 请求追踪 | http://127.0.0.1:5178/traces | 按请求查看检索、工具、调用和错误。 |
| 知识与配置 | http://127.0.0.1:5178/knowledge | 管理示例知识、索引与配置预设。 |
| API 文档 | http://127.0.0.1:8008/docs | 查看接口字段与定义。 |

页面访问令牌使用 `.env.mock.example` 中的 `API_ACCESS_TOKEN`。模拟模式使用本地模拟向量、证据摘录与模拟业务响应，适合体验执行流程，不代表真实模型的理解、生成或纠错效果。

停止并保留数据：

```bash
docker compose -p qingyu-demo --env-file .env.mock.example stop
```

默认真实模型启动使用另一组项目与数据卷。真实与模拟索引不能混用，切换模式不应靠删除已有数据库解决。

## 第一次使用

1. 在客服页填写本地访问令牌，询问“定制商品无理由退货有什么限制？”，展开引用查看原文、政策版本和来源。
2. 保持“只读业务模式”开启，询问“ORD-006 退款金额为什么不是 199 元？”，按提示确认订单、商品范围、原因与时间。
3. 需要澄清时补充已确认条件。修正事实、订单切换、取消和显式恢复的规则见[多轮业务说明](agent-and-sessions.md)。
4. 从回答进入请求追踪，核对实际证据、业务工具结果和模型调用。页面刷新后重新填写令牌，可连接当前持久任务。

所有订单、售后和物流均为虚构记录。退款预估不表示审批、到账或执行交易。

## 知识与配置页面

“导入示例知识”构建新索引但不切换默认选择。页面显示文档来源、版本与入库任务，并提供兼容索引选择和 BM25 构建操作；当前不支持任意文件上传。

版本化预设分为召回、答案、Agent、审核和复杂循环。应用后用于新请求或新任务；澄清、恢复和进行中的任务保留原配置快照。页面显示有效配置、修订和指纹，可用于确认实际启用的组合。

使用 BM25 或混合召回前先构建对应产物；定向补查和复杂循环需要匹配执行策略与审核设置。详细说明分别见[索引](index-management.md)、[召回](retrieval.md)、[答案](answer-configuration.md)和[审核](evidence-review.md)。

## 复杂任务循环

默认 `legacy` 路径使用现有路由与多步执行。可选的 `agent-loop-v1` 在读取业务与政策观察后逐次决定下一项行动：调用工具、生成候选、审核、定向补查或重写，并复用持久化结果。

循环仅接管动态任务路径。启用循环不表示全部请求都会经过它；自动路由中的快速路径仍按原执行器处理。

可以在“知识与配置”页选择以下配套预设，作为显式循环配置示例：

| 类别 | 预设 |
| --- | --- |
| Agent | `dynamic.v1.1.0.json` |
| 复杂循环 | `loop-v10-obligations.v1.10.0.json` |
| 审核 | `loop-post-required.v1.0.0.json` |

循环要求关闭旧前置检查、开启后置审核，并关闭旧路径的纠错策略。`off`、`pre-only` 或旧 `limited-correction` 不能替代配套审核配置；旧预设也不会自动升级成新契约。

服务环境方式需同时设置：

```dotenv
AGENT_CONFIG_PATH=configs/agents/dynamic.v1.1.0.json
RUNTIME_VERSION=agent-loop-v1
LOOP_CONFIG_PATH=configs/loops/loop-v10-obligations.v1.10.0.json
REVIEW_CONFIG_PATH=configs/reviews/loop-post-required.v1.0.0.json
```

重新创建后端后核对页面有效配置。只填写 `LOOP_CONFIG_PATH` 不会自动切换环境中的执行版本。启用新配置后开始新任务，旧任务不会自动迁移。

## 循环中的证据、审核与发布

循环保存目标、工具观察、证据、候选及审核结果。发现缺口时，可按明确问题补查完整政策或业务记录；没有绑定到证据的审核问题仍作为待处理问题保留，不能因引用为空而丢弃。

候选重写后需要复审，旧问题逐项关闭，并重新核对候选、证据与审核绑定。只有发布检查通过，候选才成为最终回答；未通过的文本只在受保护追踪中供核查。

预算预览提供保守的临时容量提示，不预留额度，也不授予执行许可。每次调用与最终发布仍检查实际预算。默认输入 12000、证据 6000、任务累计 60000 tokens，并共用任务的模型、工具、修复和主动时间上限。

当前循环不提供完整的循环内澄清、事实修订及部分回答流程；相关分支会受控退出。普通业务模式具备的交互能力不能直接视为循环内也已支持。

## 追踪与使用边界

对话区显示状态、进度和可发布结果；追踪页提供完整配置、候选、已取得证据、未关闭问题、审核与预算记录。用量或费用未知时为 `null`，预算估算与供应商实际用量分别保存。

复杂循环是可选能力，真实模型可能在补查、审核、输入协议或预算环节退出。机制可运行、候选合法或在线审核通过，都不证明真实业务语义正确；项目未完成完整人工语义验收，也不适合直接用于真实售后裁定。
